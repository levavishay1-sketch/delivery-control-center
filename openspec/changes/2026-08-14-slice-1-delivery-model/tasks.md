# Tasks: Slice 1 — Delivery Model and Attention Center

## Overview

Slice 1 extends the work-item model, adds Blocker, Decision, and Dependency entities, and builds the delivery control plane UI around them. Tasks are grouped into logical units, each testable and committable independently.

## Task Group 11: Dependency Graph Visualization (2 tasks) — ✅ DONE

- [x] 11.1 **Library decision** (deferred to this task by tasks.md's own note): hand-rolled SVG, not Cytoscape.js/D3/Recharts. This app has zero graph-library dependencies today; every connected neighborhood is bounded to 200 nodes (`getWorkItemDependencyGraph`'s defensive cap, in practice far smaller for a Slice-1 demo), which a simple layered layout + native SVG handles fine without the bundle-size/API-surface cost of a full graph library, and avoids the `npm install-scripts approve` gate a new dependency with a postinstall script would trigger (per CLAUDE.md). Implemented `DependencyGraph` (`src/components/DependencyGraph.tsx`): topological left-to-right layout (a node's column = the longest chain of dependencies from it down to a leaf, computed via memoized recursion with a cycle guard — defensive, since the write-path already rejects cycles), SVG `<path>` edges with arrowheads (`<marker>`) pointing from dependent to dependency, and a native `<title>` element per edge for the hover-shown reason (the spec's "on hover" option). Click (or Enter/Space, `role="button"` `tabIndex={0}` per node) sets the selected node: selected → green, everything reachable by following dependency edges from it → blue (upstream, i.e. "depends on"), everything reachable by walking edges backward → purple (downstream, "depends on this"), everything else dimmed to 35% opacity. Data source: new `getWorkItemDependencyGraph(workItemId)` (`src/domain/dependency/queries.ts`) — BFS over dependency edges in both directions from the current item, collecting the *full connected neighborhood* (not just 1-hop), since the spec's "selecting a node highlights its upstream/downstream" only makes sense if the graph shows more than the current item's immediate neighbors. Tests: `src/domain/dependency/graph.test.ts` (2 integration tests: single isolated node, and a 4-node fan-in chain reached correctly from a 2-hop-away leaf, confirming the BFS collects the whole neighborhood and nothing unrelated) plus manual verification of click/highlight/zoom below.

- [x] 11.2 Integrated into the 360° Record's Dependencies tab (`DependenciesTab` gained an optional `graph` prop; when present, renders `DependencyGraph` in place of the old "Coming soon" stub). **Deviation — not integrated into the Quick View drawer**: consistent with Task Group 8's decision to keep the drawer to reused list/detail components rather than a second copy of every feature — a full pan/zoom SVG graph doesn't fit usefully in a 400px drawer, and it's one click away via "Open full 360° Record." Responsive/interactive: `+`/`−`/"Reset view" buttons for zoom (simple, reliably touch-friendly, avoiding fragile hand-rolled pinch-gesture math for a Slice-1 feature), mouse-wheel zoom, and drag-to-pan via Pointer Events (works for touch drag natively, no separate mobile code path needed); `touch-none` on the SVG so browser scroll-gesture doesn't fight the pan. **Bug found and fixed during live verification**: the pan handler called `setPointerCapture` on every pointerdown anywhere in the SVG, including on top of a node — in Chromium this redirects the synthesized `click` event to the capturing element instead of the node, so clicking a node silently did nothing (no highlight change) even though the click handler was correctly wired. Fixed by only starting a pan-drag (and capturing the pointer) when the press originates on the SVG background itself (`e.target === svgRef.current`), not on a node. Verified via a real Playwright-driven Chromium session against a live 3-node dependency chain: initial render showed the correct topological layout and colors (selected item green, its dependency chain blue); clicking the leaf node re-colored it green and the other two purple (correctly re-computed as its downstream); the zoom-in button visibly enlarged the nodes. No console/page errors. Cleaned up fixture data afterward. Build/Lint/Tests: `npm run build` ✓, `npm run lint` ✓, `npm test` (78/78 passing, 2 new). Commit: "Implement dependency graph visualization".
