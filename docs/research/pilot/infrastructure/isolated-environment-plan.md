# תוכנית מימוש: סביבת פיילוט מבודדת במכונה וירטואלית נפרדת

**מצב:** תוכנית לסקירה בלבד. לא הותקן דבר, לא נוצרה מכונה וירטואלית, ולא שונו הרשאות, חומת אש או הגדרות אבטחה. אין כאן קריאה למודל. הפרוטוקול המוקפא לא שונה, ואף פרמטר פתוח לא נקבע. מימוש יתחיל רק אחרי האישורים בסעיף 10.

**בסיס:** ההמלצה באפשרות א של `os-isolation-proposal.md`, הבדיקה לקריאה בלבד של המחשב בדוח שלב 4, ותיעוד Claude Code הרשמי שנקרא ב-2026-09-29 כטקסט: הדפים network-config, iam, setup, data-usage, settings ו-managed-settings. כל עובדה על Claude Code כאן מגיעה מהדפים האלה. כל מה שלא אומת מסומן `UNKNOWN`.

---

## 1. הארכיטקטורה בקצרה

שני צדדים, עם גבול מכונה ביניהם:

| צד | מה רץ בו | מה אין בו |
|---|---|---|
| **המארח**, מחשב Windows ייעודי שמנוהל בידי IT, עם Hyper-V | רתמת DCC, הפרוקסי, יומן הראיה, העותק המשותף של הריפו, בדיקות הייחוס, המניפסטים וההחלטה על שחזור המכונה | אין עליו הרצת סוכן |
| **המכונה הווירטואלית של הסוכן** | Windows, כלי הבנייה, Claude Code בגרסה נעוצה, `job-run.exe`, ועותק הסוכן של הריצה הנוכחית | אין בה חומרי רתמה בזמן שהסוכן רץ, אין תיקייה משותפת עם המארח, אין הפרופיל שלך, ואין `~/.claude` שלך |

**העיקרון:** חומרי הרתמה נשארים על המארח כל עוד הסוכן רץ, והמכונה הווירטואלית אינה יכולה לפנות אל המארח. לכן הדרישה של סעיף 5.4 פריט 6, שחומרי הרתמה מחוץ להישג הקריאה של הסוכן, מתקיימת בגבול המכונה ולא בהרשאות קבצים בתוך אותה מערכת. הדירוג, שדורש את בדיקות הייחוס, רץ אחר כך בשלב נפרד, על מכונה ששוחזרה ובלי רשת.

**מחזור ריצה אחת:**

1. המארח משחזר את המכונה לנקודת הבסיס הקפואה.
2. המארח מעתיק פנימה את עותק הסוכן, `S_c` ועליו קבצי הזרוע, ואת קבצי הריצה. בדיקות הייחוס אינן מועתקות.
3. הסוכן רץ בחשבון `pilot-agent`, בתוך Job Object, והרשת היוצאת היחידה היא הפרוקסי שעל המארח.
4. המארח מוציא את עץ העבודה, התמליל וקובץ המצב, ובודק אותם.
5. המארח משחזר שוב את המכונה ומנתק אותה מהרשת לגמרי.
6. המארח מעתיק פנימה את העץ שהוצא ואת בדיקות הייחוס, מריץ את הדירוג ומוציא את התוצאה.
7. המארח משחזר את המכונה לבסיס.

## 3. גבולות מערכת הקבצים

### 3.1 מה הסוכן יכול לקרוא ולכתוב

החשבון `pilot-agent` הוא משתמש רגיל בלי הרשאות מנהל, ורק בו הסוכן רץ.

| מיקום בתוך המכונה | קריאה | כתיבה | למה |
|---|---|---|---|
| `C:\pilot\work\<run>`, עותק הסוכן | כן | כן | תחום העבודה |
| `C:\pilot\work\<run>\.claude-run`, ה-`CLAUDE_CONFIG_DIR` של הריצה | כן | כן | הגדרות וסשן של Claude Code לריצה אחת בלבד. התיעוד: כשהמשתנה מוגדר, Claude Code שומר שם הגדרות, היסטוריה וקובץ אישורים |
| הפרופיל של `pilot-agent` ו-`%TEMP%` שלו | כן | כן | ברירת המחדל של Windows למשתמש. מתאפס בשחזור |
| `C:\Program Files`, `C:\Windows` וכלי הבנייה | כן | לא | ברירת המחדל של Windows למשתמש רגיל |
| `C:\Program Files\ClaudeCode\managed-settings.json` | כן | לא | הגדרות מנוהלות שהסוכן אינו יכול לשנות, לפי תיעוד managed-settings |
| פרופילים של חשבונות אחרים במכונה | לא | לא | ברירת המחדל של Windows |

### 3.2 איך נמנעת גישה מחוץ לתחום

1. **חומרי הרתמה אינם במכונה בזמן שהסוכן רץ.** המארח מעתיק פנימה רק קבצים מרשימה סגורה, ורושם את הגיבוב של כל אחד. בדיקות הייחוס נכנסות רק בשלב הדירוג, על מכונה ששוחזרה ובלי רשת.
2. **המכונה אינה יכולה לפנות אל המארח.** אין תיקיות משותפות. Enhanced Session כבוי. חומת האש בתוך המכונה חוסמת כל יציאה חוץ מפורט הפרוקסי, סעיף 4, ולכן גם SMB אל המארח חסום.
3. **המשתמש אינו מנהל,** ולכן אינו יכול לשנות את חומת האש, את ההגדרות המנוהלות או את הרשאות המערכת.
4. **כל ריצה מתחילה מאותו בסיס.** שחזור נקודת הבסיס מוחק כל מה שהריצה הקודמת השאירה, כולל משימות מתוזמנות שהסוכן יצר לעצמו.

**מה נשאר קריא, ולמה זה מקובל:** הסוכן יכול לקרוא כל מה שמשתמש רגיל קורא בתוך המכונה. במכונה אין שום מידע של פיילוט אחר, של המארח או שלך.

## 4. גבולות רשת

### 4.1 הטופולוגיה

- **מתג פנימי ב-Hyper-V,** `pilot-internal`, מסוג Internal. הוא מחבר רק את המכונה ואת המארח, בלי NAT ובלי שיתוף חיבור האינטרנט. למכונה אין נתיב לאינטרנט.
- **הפרוקסי של הרתמה רץ על המארח** ומאזין רק על הכתובת של המארח במתג הפנימי. הרשימה המותרת בזמן ריצת סוכן: `api.anthropic.com:443` בלבד. אם הבדיקה תראה שנדרש יעד נוסף, למשל `platform.claude.com` לחידוש אסימון, הוא יתווסף רק בהחלטה מתועדת.
- **חומת האש בתוך המכונה,** שמוגדרת בבנייה בידי מנהל: יציאה ברירת מחדל חסומה בכל הפרופילים, וכלל יציאה יחיד שמתיר TCP לכתובת הפרוקסי ולפורט שלו. גם IPv6 חסום.
- **אין DNS.** פורט 53 חסום ביציאה, ואין שרת DNS בהגדרות הרשת. הפרוקסי על המארח מתרגם שמות. בפרוקסי מסוג CONNECT, Claude Code שולח את שם השרת ולא כתובת.
- **בשלב הדירוג** המכונה מנותקת מהמתג לגמרי.

### 4.2 הגדרות Claude Code שמצמצמות תעבורה, כולן מהתיעוד

נקבעות ב-`managed-settings.json` שהסוכן אינו יכול לשנות, או במשתני הסביבה של הריצה:

| הגדרה | מה היא עושה, לפי התיעוד |
|---|---|
| `HTTPS_PROXY` | Claude Code מכבד אותו לכל תעבורת HTTPS שלו |
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` | מבטל את הטלמטריה האופציונלית, כולל שני שרתי Datadog |
| `DISABLE_TELEMETRY=1` ו-`DISABLE_ERROR_REPORTING=1` | מבטלים מדדים ודיווחי שגיאה |
| `DISABLE_UPDATES=1` | חוסם כל נתיב עדכון, כדי שהגרסה לא תשתנה באמצע |
| `ENABLE_CLAUDEAI_MCP_SERVERS=false` | מונע משיכת מחברי MCP מ-`mcp-proxy.anthropic.com` |
| `CLAUDE_CODE_DISABLE_OFFICIAL_MARKETPLACE_AUTOINSTALL=1` | מונע התקנה אוטומטית מהמרקטפלייס הרשמי. הדגל של התעבורה הלא-חיונית אינו מכסה אותה, לפי התיעוד |
| `skipWebFetchPreflight: true` בהגדרות המנוהלות | מבטל את בדיקת הבטיחות של WebFetch מול `api.anthropic.com`. גם אותה הדגל של התעבורה הלא-חיונית אינו מכסה |
| WebFetch ו-WebSearch חסומים בכלים של הריצה | סעיף 3.2 בפרוטוקול |

**האכיפה אינה תלויה במשתנה הפרוקסי.** לפי התיעוד, בהרצה מקומית Claude Code קורא את `HTTPS_PROXY` גם מקובצי ההגדרות של הריפו, כך שריפו יכול להפנות אותו. זה לא משנה כאן: חומת האש במכונה חוסמת כל יעד חוץ מהפרוקסי, ולכן הפניה אחרת פשוט נכשלת.

**מה שאינו ניתן לסינון:** לפי התיעוד, `api.anthropic.com` נושא גם דגלי פיצ'רים ורישום אירועי טלמטריה. `DISABLE_TELEMETRY` והדגל של התעבורה הלא-חיונית מבטלים את הערכת דגלי הפיצ'רים. הפרוקסי רואה רק את שם השרת ואינו פותח את ה-TLS, ולכן האם בקשה שאינה בקשת מודל עדיין מגיעה ליעד המותר: `UNKNOWN`. שער על המארח שמסיים את החיבור ורואה כל בקשה היה סוגר את זה. זו החלטה פתוחה, סעיף 10.2.

### 4.3 איך נבדקים חיבור ישיר ו-DNS

הבדיקות רצות כ-`pilot-agent` בתוך המכונה. כל אחת צריכה להיכשל בסירוב או בהיעדר נתיב, והמאזינים על המארח לא אמורים לקבל דבר:

| בדיקה | מה נחשב PASS |
|---|---|
| חיבור TCP ישיר לכתובת IP באינטרנט, פורט 443 | אין חיבור. אין נתיב, או סירוב של חומת האש |
| חיבור TCP ישיר למאזין שהמארח מפעיל על פורט שאינו פורט הפרוקסי | אין חיבור, והמאזין לא קיבל דבר |
| UDP לפורט 53 של שרת ציבורי, ו-UDP לפורט 443 | אין תשובה, ורישום הסירוב של חומת האש במכונה, אם הרישום פעיל |
| תרגום שם חיצוני במכונה | נכשל |
| חיבור IPv6 החוצה | אין חיבור |
| גישה ל-`\\<host>\c$` | נכשלת |
| CONNECT דרך הפרוקסי ליעד שאינו ברשימה | 403, והפרוקסי רשם אותו |
| CONNECT דרך הפרוקסי ל-`api.anthropic.com:443` ולחיצת יד TLS | מצליח, בלי שליחת בקשה ל-API ובלי קריאת מודל |

## 5. Claude Code בלי הפרופיל, האישורים או `~/.claude` שלך

1. **התקנה נפרדת.** Claude Code מותקן במכונה בידי IT, בגרסה של U12, ונבדק מול החתימה והמניפסט. שום קובץ לא מועתק מהמחשב שלך. הקובץ הקיים אצלך נמצא תחת הפרופיל שלך ולא ישמש.
2. **תיקיית הגדרות לכל ריצה.** `CLAUDE_CONFIG_DIR` מצביע לתיקייה בתוך עותק הריצה, שנמחקת בשחזור. לפי התיעוד, כשהמשתנה מוגדר, קובץ האישורים, ההגדרות, ההיסטוריה והתוספים נשמרים שם.
3. **אישורים ייעודיים לפיילוט, בהחלטתך.** לפי סדר הקדימות בתיעוד, שתי אפשרויות מתאימות להרצה בלי דפדפן:

| אפשרות | מה זה | השלכה |
|---|---|---|
| **מפתח API של Console,** `ANTHROPIC_API_KEY`, ב-workspace ייעודי לפיילוט עם תקרת הוצאה | זהות של workspace ולא של אדם | נפרד לגמרי מהמנוי האישי שלך. קל לסובב אחרי הפיילוט |
| **אסימון שנתי מ-`claude setup-token`,** `CLAUDE_CODE_OAUTH_TOKEN` | מקושר לחשבון שלך | ההרצות נרשמות על הזהות שלך. ייתכן שנדרש `platform.claude.com` לחידוש: `UNKNOWN`, ייבדק |
| **שער על המארח.** הסוכן פונה דרך `ANTHROPIC_BASE_URL` לשער על המארח, והשער מוסיף את המפתח האמיתי | האישור לא נכנס למכונה בכלל | רכיב חדש שצריך לבנות ולבדוק. ההתנהגות של Claude Code מול שער כזה לא נבדקה מול התיעוד בתוכנית הזו: `UNKNOWN` |

4. **אני לא נוגע באישור.** אתה או IT שמים אותו במאגר האישורים של Windows על המארח, תחת `pilot-harness`. הרתמה קוראת אותו בזמן ריצה ומזריקה אותו רק לסביבה של תהליך הסוכן. הוא לא נכתב לדיסק של המכונה ולא מופיע בקבצים שהרתמה כותבת.
