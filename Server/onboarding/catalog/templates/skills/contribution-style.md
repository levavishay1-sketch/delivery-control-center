# contribution-style

The rules are the maintainers': {{contributing_list}}. Read them at the start of a task; they override any general habit.

## Steps

1. Read the files above — in full when short; the sections on commits, pull requests, tests and style when long. Note what is mandatory.
2. Shape the work to match: branch naming, commit message format (a sign-off, a scope prefix, an issue reference), the pull request template, the tests a change must ship with, the tooling a change must pass.
3. Where the rules say to run something (a formatter, a linter, a generator), run it and include the result.
4. When a rule cannot be followed here (a tool is missing, a sign-off you cannot give), say which one instead of quietly skipping it.
5. In the pull request, say which rules you followed and where you departed, in one short list.
